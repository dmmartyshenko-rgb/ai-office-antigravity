# Журнал: birzha-analitik

## 2026-09-22 — Домен создан, харнес построен
Запрос: харнес для аналитики и инвестирования в бумаги через российскую биржу
(счета Финам и Тинькофф). Присланный процесс был написан под рынок США (Yahoo
Finance, GICS, EPS в $) — переработан под MOEX.

Построено на ветке `claude/nice-mccarthy-xla25a`: скилл `birzha-analitik`
(пайплайн 8 шагов), 3 справочника (источники RU, секторные метрики, риски РФ),
2 шаблона (отчёт + карточка сделки с HITL-гейтом), 2 скрипта (moex_fetch.py на
MOEX ISS API, check_report.py — валидатор), рабочий пример на SBER.

Ключевые решения:
- **Не переписывать US-процесс, а строить под MOEX:** первоисточники MOEX ISS /
  e-disclosure / cbr.ru; секторные метрики (P/BV для банков, EV/EBITDA для
  нефтегаза); RU-риски (санкции, редомициляция, дивполитика, free-float, гос-доля).
- **Обязательный Шаг 6** — оценка против безрисковой ставки (ОФЗ/ключевая ставка):
  особенность рынка РФ, которой не было в исходном процессе.
- **Human-in-the-Loop жёстко:** харнес готовит карточку сделки, ордер ставит
  человек вручную; торговых ключей нет и не запрашиваются.
- **Egress-факт:** из этой облачной сессии MOEX и cbr.ru закрыты политикой (403,
  подтверждено curl и WebFetch). Не обходил — заложил в харнес честно: живые
  данные тянутся локально, в сессии — вторичные источники, недостижимое
  помечается `⛔`.

Доказательства: `moex_fetch.py SBER` чисто отработал egress (код 2, понятное
сообщение); `check_report.py` на шаблоне → FAIL (92 заглушки пойманы), на
заполненном примере SBER → OK; `check_map.py` — зелёный.
